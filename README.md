# Lagebild

TAK-ähnliche Lagebild-PWA (Blue Force Tracking) mit Schweizer Karten (swisstopo) und taktischen Zeichen (APP-6D via milsymbol). Ausbildungs- und Testmittel.

Spec: [docs/spec.md](docs/spec.md) · Vertrag: [shared/protocol.ts](shared/protocol.ts)

## Entwicklung

```bash
npm install
LAGE_ERSTELL_PASSWORT=dev npm run dev   # Server :8080 (Daten in ./data) + Vite :5173 mit Proxy für /api und /ws
npm run check                            # tsc (Server/Vertrag) + svelte-check (Client)
npm test                                 # vitest: Server, Client-Logik, Features
npm run build                            # client/dist inkl. Service Worker
LAGE_ERSTELL_PASSWORT=… npm start        # Produktion: liefert client/dist + API + WebSocket (PORT, DATA_DIR)
npm run e2e                              # Playwright: baut, startet Server auf PW_PORT (8797) mit frischem DATA_DIR, alle Projekte
npx playwright test --project=quer       # nur die Vorgabe (Handy quer)
E2E_BILDER=1 npm run e2e                 # dazu die Doku-Bilder in docs/screens neu schreiben (sonst keine Bildschirmfotos)
```

### Android-App (Capacitor)

Die App ist dieselbe Svelte-Oberfläche in einer APK (`ch.arvuna.lagebild`, `capacitor.config.ts`, `android/`). Sie startet ohne Netz; API und WebSocket gehen an `https://lage.arvuna.ch` (`client/src/lib/umgebung.ts`, Build-Zeit überschreibbar mit `VITE_SERVER_URL`). Die PWA bleibt daneben unverändert.

```bash
npm run build:app          # Oberfläche ohne Service Worker nach client/dist-app (wird von cap sync in die APK kopiert)
deploy/android.sh          # kompletter Ablauf: Oberfläche bauen, cap sync, Gradle in LXC 120, APK nach /root/projekte/lagebild-apk/
VARIANTE=debug deploy/android.sh   # Debug-Build statt signierter Release-APK
```

- **Gradle** läuft in LXC 120 `android-build` (JDK 21 – Capacitor 8 verlangt es –, SDK unter `/opt/android-sdk`, kein Node). `android.sh` kopiert `android/` plus die nativen Teile der Plugins aus `node_modules/@capacitor*` hinüber und holt die APK zurück.
- **versionCode** = Minuten seit 1.1.2026 (steigt mit jedem Bauen), **versionName** = `1.0.<Commit-Anzahl>`.
- **Signatur:** Keystore `/root/.config/lagebild/lagebild.jks`, Passwort daneben in `keystore.pass` (beide 600, nie im Git, einmalig vom Skript erzeugt). Geht er verloren, lässt sich die App nicht mehr aktualisieren, nur neu installieren: Sicherung anlegen.
- **Siegel-Schlüssel (Live-Update):** privat `/root/.config/lagebild/update-signatur.pem` (ECDSA P-256, PKCS#8, 600, nie im Git, nie auf LXC 124), erzeugt mit `node deploy/siegel.mjs schluessel` (gibt auch den öffentlichen Schlüssel als JWK aus). Der öffentliche steht in `client/src/lib/updateSchluessel.ts`. **Sichern** wie den Keystore. Bei Verlust (oder Verdacht auf Abfluss): neuen Schlüssel erzeugen, öffentlichen in `updateSchluessel.ts` eintragen, neue APK bauen und verteilen, `deploy/min-native-code` auf deren versionCode setzen; installierte Apps mit dem alten Schlüssel nehmen danach keine Live-Updates mehr an und brauchen die neue APK.
- **Hintergrund-GPS** (Einstellung «Position im Hintergrund senden», nur in der App, Vorgabe aus): `@capacitor-community/background-geolocation` als Foreground-Service mit Dauer-Benachrichtigung; `android.useLegacyBridge` in der Config ist dafür Pflicht. Berechtigungen: Standort (fein/grob), `FOREGROUND_SERVICE_LOCATION`, `POST_NOTIFICATIONS`, Kamera; `ACCESS_BACKGROUND_LOCATION` bewusst nicht.
- **Live-Update der Oberfläche** (Plugin `@capgo/capacitor-updater`, nur manuell, ohne Cloud; Recherche `docs/recherche/live-update.md`): Beim Start, bei `visibilitychange` und alle 30 min liest die App `/app/web.json` (`webCode`, `url`, `sha256`, `minNativeCode`, `protokoll`, `stufe`, `sig`). Ist `webCode` höher als der laufende Stand (`__WEB_CODE__`), `minNativeCode` ≤ installierter versionCode und das **Siegel** gültig, lädt sie `web-<webCode>.zip` im Hintergrund (nur von der eigenen https-Basis, SHA-256 muss stimmen) und zeigt «Neue Version bereit» mit «Neu laden» und «Später». Aktiviert wird **nur beim Antippen** von «Neu laden», nie von selbst beim Start oder beim Wechsel in den Hintergrund; ein schon geladener, nicht aktivierter Stand wird beim nächsten Start wieder angeboten. Ohne Update läuft die App normal weiter.
  - **Siegel:** ECDSA P-256 mit SHA-256 über die UTF-8-Nachricht `lagebild-web|<webCode>|<minNativeCode>|<protokoll>|<stufe>|<sha256-hex>`, Signatur IEEE P1363 (r‖s, 64 Byte) base64url in `sig`. Damit gilt eine Signatur nur für genau diesen Stand (Inhalt, Mindest-APK, Stufe und Protokoll lassen sich nicht austauschen). Geprüft wird vor dem Download mit WebCrypto gegen den fest eingebauten öffentlichen Schlüssel `client/src/lib/updateSchluessel.ts` (steckt in der APK und in jedem gesiegelten Stand, wird nie vom Server übernommen). Fehlt das Siegel oder stimmt es nicht: Stand ignorieren, nichts laden.
  - **Stufe** (gesiegelt): `normal` – zusätzlich «Diese Version überspringen» (webCode pro Gerät gemerkt, ein höherer erscheint wieder), «Später» blendet bis zum nächsten Start/Zurückholen aus; `wichtig` – kein Überspringen, nach «Später» bleibt ein kleiner Hinweis sichtbar; `sicherheit` – «Sicherheitsupdate bereit» in Warnfarbe, kein Überspringen, bleibt klein sichtbar.
  - **Protokoll:** `PROTOKOLL_VERSION` aus `shared/protocol.ts` (Hauptversion des Vertrags). Bringt ein Stand eine andere, wird er trotzdem angeboten, mit «Update nötig, um mit neueren Geräten zu arbeiten». Stand und Protokoll stehen in Menü › Über. Der neue Stand ruft nach dem Mounten `notifyAppReady()` (`appBereit()` in `main.ts`); kommt das nicht innert 20 s, fällt das Plugin auf den letzten guten bzw. den eingebauten Stand zurück, und dieses Bundle wird nicht erneut geladen. Eine neue APK entfernt geladene Bundles (`resetWhenUpdate`); der eingebaute Stand ist dann der Rückfall. Origin (`https://localhost`) und damit localStorage/IndexedDB/Cache Storage bleiben beim Wechsel gleich.
- **Service Worker** ist in der App aus; für native Änderungen fragt sie beim Start und bei `visibilitychange` `/app/version.json` ab und zeigt «Neue App-Version · Herunterladen».

E2E braucht einmalig `npx playwright install chromium`. Die Tests (`e2e/*.e2e.ts`) spielen eine ganze Lage mit Leitung und Teilnehmer durch. **Vorgabe ist das Handy quer** (Juan 31.10.: «die Hauptnutzung (98 %) wird in landscape genutzt»): Android FHD+ 2340×1080 bei DPR 2.75 = 851×393 CSS-px, mit Touch (`playwright.config.ts`, Masse auch in `e2e/hilfen.ts`). ## Betrieb

- **Wo:** LXC 124 `lagebild` (192.168.1.74:8080), öffentlich als https://lage.arvuna.ch über den CF-Tunnel `proxmox-ssh` des Proxmox-Hosts.
- **Deploy:** `deploy/deploy.sh` auf dem Host. Das Skript baut, spielt die App nach `/opt/lagebild/app` ein und startet den Dienst `lagebild` neu. Die Daten unter `/var/lib/lagebild` bleiben erhalten.
- **UI-Änderung ausliefern (Live-Update):** `deploy/deploy.sh` genügt. Es liefert die PWA und anschliessend über `deploy/web.sh` das App-Bundle: `npm run build:app` → `web-<code>.zip` + gesiegeltes `web.json` (`deploy/siegel.mjs`; webCode = Minuten seit 1.1.2026, webName = `1.0.<Commit-Anzahl>`, SHA-256, `minNativeCode` aus `deploy/min-native-code`, `protokoll`, Stufe aus `STUFE=normal|wichtig|sicherheit`, Vorgabe normal; ohne Siegel-Schlüssel bricht es ab) nach `/var/lib/lagebild/app/` in LXC 124 (Datenverzeichnis, kein Neustart; `web.json` zuletzt, die letzten 3 Bundles bleiben). Einzeln: `deploy/web.sh`. **Neue APK nötig** nur bei nativen Änderungen (Plugins, `AndroidManifest`, `MainActivity`, `capacitor.config.ts`): `deploy/android.sh`, `deploy/apk.sh`, danach in `deploy/min-native-code` den versionCode dieser APK eintragen (steht in `/root/projekte/lagebild-apk/version.json`), damit ältere Apps neue Web-Stände nicht übernehmen und stattdessen «Neue App-Version · Herunterladen» zeigen.
- **Android-App ausliefern:** `deploy/apk.sh` legt `lagebild.apk` und `version.json` nach `/var/lib/lagebild/app/` in LXC 124 (nicht im Git, kein Neustart nötig). Der Server liefert sie als `/app/lagebild.apk` und `/app/version.json`; im Browser erscheint unter Menü › Über «Android-App installieren», sobald `version.json` da ist. `Access-Control-Allow-Origin` setzt der Server nur für die App-Ursprünge `https://localhost` und `capacitor://localhost` (`server/src/sicherheit.ts`); die API nutzt Bearer-Tokens statt Cookies, der WebSocket prüft keinen Origin.
- **Geheimnis:** `/etc/lagebild.env` enthält nur `LAGE_ERSTELL_PASSWORT` (root, 600). So ersetzt du es auf dem Host: `pct exec 124 -- bash -c 'read -rsp "Erstell-Passwort: " p; echo; umask 077; printf "LAGE_ERSTELL_PASSWORT=%s\n" "$p" > /etc/lagebild.env; systemctl restart lagebild'`
- **Proxy:** `TRUSTED_PROXY=192.168.1.100` steht in der Unit, weil cloudflared auf dem Host läuft. Nur von dort gilt `CF-Connecting-IP` für die Rate-Limits, für alle anderen Verbindungen gilt die Socket-IP.
- **Logs:** `pct exec 124 -- journalctl -u lagebild -f`
